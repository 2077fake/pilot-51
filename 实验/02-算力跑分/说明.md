# 实验 02-算力跑分 说明.md

- 日期：2026-10-23 22:29 ~ 23:00
- 需求：用户指令「跑算力」——让 51 芯片实测运算速度，曲线面板可看
- 最终结果：**15,108 次/秒 16 位乘加**（66.2 µs/次 @ 实测 10.993 MHz、12T 机周），窗口严格 8 个溢出周期后曲线零抖动

## 设计（最终版 main.c）

- 跑分单元：`x = x * 3141 + 12345`（16 位乘加，链式依赖防优化）
- 计时：Timer0 模式 1 自由计数（TMOD 高 4 位保留 Timer1 波特率发生器）；**先等一次 TF0 溢出沿再清零起测**——每个窗口从同相位起跑，严格 8 次溢出 = 524288 拍 = 568.9 ms
- 换算：per_sec = ops × 17578 / 10000（= ×921600/524288）
- 输出：`uart_curve(per_sec)` 单通道上曲线；终端打 `ops=… per_sec=… x=…`（x 可离线复算验证正确性）；P2.0 LED 每 0.6~0.7 s 心跳
- 只改 main.c；uvproj/uart_put.h/c 未动（红线遵守）

## 例外清单（单列）

1. **曲线协议语义更正**：前端把 `v:` 行逗号分隔的每个值各画一条序列（多通道），不是 项目.md 原来写的「按 a 画序列」——T5 的「k/n 同轴压扁」正是此因。固件因此从 `uart_curve2(1,per_sec)` 改 `uart_curve(per_sec)`。项目.md 已更正。
2. **v1/v2 报数差 13% 之谜（已定位）**：窗口起点相位随打印时长漂移，实际窗口在 7P~8P（497.7~568.9 ms）间摆，换算系数却固定按 8P 算 → 同一真实速度（~15.1k/s）报出 15043 与 13313 两种数。边缘同步后窗口恒 8P，读数唯一且平。
3. **第三次烧写 90 s 窗口未握手**（用户未及时断电），按 SKILL 重挂一轮即成；未硬耗。
4. **webui 终端时间戳折行 bug（用户点名立项）**：`.tline` 时间戳列固定 76px 放不下 12 字符（实际 84px）+ `word-break:break-all` 任意断字 → 从毫秒中间掰开。修复：列改 `max-content` + `.ts` 加 `white-space:nowrap`。CDP 实测 32 行 0 折行、行高统一 19px。webui 只读红线按流程由用户立项后解除一次。
5. **/api/state 没有 last_flash 字段**（SKILL.md 步骤 3 原文与实现不符）→ 改为轮询 `GET /api/job?id=`。SKILL.md 已更正。
6. **printf 吃 JSON 反斜杠**：`printf '{"...\\02-..."}'` 把 `\\` 缩成 `\`，`\t` 再变制表符 → 后端报「越界路径已被拒绝」。改用正斜杠路径解决。
7. C280 'j' unreferenced：删空转循环时忘删声明，重编即净。
8. L16 良性警告随调用变动在 `uart_curve` / `uart_curve2` 之间移动，均忽略。
9. CDP 探针 Chrome 退出后 profile 目录删不掉（句柄未放）→ 先按 CommandLine 过滤杀净进程树再删。
