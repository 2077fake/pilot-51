# 实验 03-算力压榨（2026-10-24）

## 目标

用户指令「继续跑，压榨它的性能」。约束：op 定义不变——链上一步 `x = x*3141+12345 (mod 65536)` 算一次 op，与实验02 的 15108 次/秒直接可比。只许优化实现，不许换更便宜的运算。

## 设计：A/B/C 三实现同板交替，一次烧写拿到对照数据

同一固件里三条实现轮流各跑一个 8 溢出计时窗口（524288 拍 ≈ 568.9ms，换算 per_sec = ops×17578/10000，与实验02 完全一致），同一条链 x 从 A 流到 B 再流到 C：

| 档 | 实现 | 关键差异 |
|---|---|---|
| A | 实验02 原始循环逐字复制 | `?C?IMUL` 库乘 + unsigned long 计数 |
| B | 16 位乘拆 3 次 8 位 MUL | uint 计数、TF0 每 4 步一查、循环体 ×4 展开 |
| C | 只取低位字节的 3 次 MUL | x 用 x_lo/x_hi 双 uchar 状态、ops 按块 +4、uchar 溢出计数 |

曲线三通道：每轮 A/B/C 各一窗口后发 `v: perA,perB,perC`（模板只有 curve/curve2，三值行用 uart_send_str + uart_put_num 手拼，不碰模板）。

## 取证方法（本轮方法论核心）

1. **穷举验算先于烧写**：STEP/STEP2 公式在 Python 里按 uchar/uint 回绕语义逐行转录，对 65536 个输入全量对照参考链，0 失配才编译。
2. **指令级对账**：.lst 无汇编，用 C51 命令行出汇编列表（只诊断、不动 uvproj）：
   `C51 main.c "SRC(bench.src)" "INCDIR(C:/Keil_v5/C51/INC;.)" "OBJECT(bench_diag.obj)"`
   逐条数拍数：A = 35（非乘）+ 26（?C?IMUL）= 61.0；B = 53 + 摊销 2.75 ≈ 56.7——与实测 61.0 / 56.7 拍/步**完全吻合**，模型可信。
3. **真机跨实现链验证**：53 个连续窗口报告（A/B/C 混流）逐一核对 `x_i = f^{ops_i}(x_{i-1})`，0 断点——证明 C 的实现与参考函数严格等价，快得合法。

## 三档优化要点（汇编证据）

- A 的 61 拍里：`?C?IMUL` 库乘 26 拍、unsigned long ops++ 12 拍、TF0 逐拍查 + 循环头 ~9 拍。
- B 的教训：`(u&0xFF)<<8` 拆字节搬运 8 拍、`lo*0x0C` 整个 MUL 的高位字节白算、lo/hi 每步拆装 4 拍——只省 4.3 拍。
- C 的洞察：**u 的高 8 位本来就被丢弃** → 后两次 MUL 只需要 A 寄存器的低位积；x_lo/x_hi 常驻寄存器（R4/R1），免 16 位拆装。单步汇编清点 38 拍（3×MUL=12 + 搬运 26），实测 41.7 拍/步（差值是计数与循环摊销）。

## 实测结果（捕获 53 窗口，每档 ops 恒定 = 零抖动）

| 档 | ops/窗口 | per_sec | vs A | 拍/步 |
|---|---|---|---|---|
| A | 8595 | 15108 | — | 61.0 |
| B | 9240 | 16242 | +7.5% | 56.7 |
| C | 12560 | 22077 | **+46.1%** | 41.7 |

per_sec 换算核对：ops×17578÷10000 逐行全对。曲线统计面板 `15108 ~ 15108 | 16242 ~ 16242 | 22077 ~ 22077`。

1. **链核对脚本第一版方向写反**：用 `f(x_prev, ops_prev)` 应为 `f(x_prev, ops_current)`，报了 52 个假断点；更正后 0 断点。是脚本 bug，不是固件问题——记入防再犯。
2. **图例断言 legend=4**：第 4 个子节点是 updateLegend 尾部追加的「Hz · 采样 N」计数 span，非多余序列。
3. **调试台服务掉了**：会话恢复时 8765 无监听（前会话服务进程已退出），按 SKILL 用 调试台.bat 重起；重起后复查 CH340 口仍 COM10。
4. **烧写窗口失败 1 次**（用户未及时冷启动），按 SKILL 挂第二个窗口成功。
5. `bench.src` / `bench_diag.obj` 是 C51 命令行诊断产物，留在本目录备查；探针 Chrome profile 已清理（首轮清理因 bash 吞 `$_` 失败，改 .ps1 脚本后干净）。
6. 左栏「工程」面板显示页面默认选中的 51模板 工程，与实验03 无关，截图里出现属正常。
7. GBK 控制台里本实验验证输出中的 `ȫ` 乱码是 agent 抓包管道显示问题，数据文件本身 UTF-8 无损。
8. ops_c 为 uint，窗口上限 65535 ops ≈ 115k/s，当前 22077 有 5 倍裕量，不设防溢出。

## 遗留 / 边界

- C 档 41.7 拍里 MUL 只占 12 拍，剩 ~30 拍是 C 层搬运/循环/计数开销。再往下压需要内联汇编（#pragma SRC → .SRC 要改 uvproj 源列表，属红线升级，需用户立项）。
- 换更便宜的运算（改链常数、改 op 定义）不算压榨，本实验不采纳。
- 串口打印每窗口 ~40 字节 ≈ 42ms，全部发生在窗口外（边缘同步等待吞掉），不影响测量。
